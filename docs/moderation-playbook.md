# Vivah Australia Moderation Playbook

## Goal

Keep member safety decisions consistent, auditable, and reversible where appropriate. This playbook is for moderators and admins handling profile reviews, verification, reports, and escalation decisions.

## Profile Review Flow

### Approve

Use when:

- profile information is complete enough for publication
- no obvious policy or trust issue is present
- submitted photos/content fit the platform rules

### Needs changes

Use when:

- the profile is legitimate but incomplete or unclear
- text/photos need corrections before approval
- there is not enough reason to reject or suspend the member

Include a clear member-facing reason so the member knows what to fix.

### Reject

Use when:

- the submitted profile content is not acceptable for publication
- identity/trust signals are inconsistent enough that the current submission cannot be approved
- a new submission should be required before the member becomes visible

## Verification Review Flow

- Always use the signed preview flow for verification documents.
- Do not copy raw document URLs into chats, tickets, or notes.
- Approve only when the submitted document type matches the requested verification and the document is readable enough to support the decision.
- Reject with a concise reason that can guide the next submission.

## Reports Workflow

### Dismiss

Use when the report does not show a policy issue or lacks enough substance after review.

### Warn

Use for lower-severity conduct issues where education is more appropriate than immediate restriction.

### Suspend

Use when behavior is unsafe, repeated, or serious enough to pause access while further review happens.

### Ban

Use when there is clear severe abuse, fraud, or repeated harmful behavior that should permanently remove access.

### Remove content

Use when the unsafe item is specific to a post/comment/content object and should be taken down without necessarily banning the member immediately.

## Block / Safety Escalation Notes

- Blocks should leave historical conversations visible but locked where that behavior is already implemented.
- If a report indicates stalking, coercion, impersonation, or document misuse, escalate to an admin instead of treating it as a normal content clean-up task.
- Preserve auditability: moderation actions should always happen through admin routes so audit logs remain complete.

## Internal Notes Guidance

- Write factual notes, not speculation.
- Include what was reviewed, what action was taken, and why.
- Avoid copying sensitive document details into notes unless strictly necessary for future review.

## When to Escalate to Admin

- possible payment abuse or refund manipulation
- identity/document concerns that could affect policy or legal handling
- repeated safety reports across multiple surfaces
- any case where suspension vs ban is not obvious
